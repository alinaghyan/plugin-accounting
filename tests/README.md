# برنامه آزمون

این مخزن در حال حاضر اسکلت و مستندات دارد؛ هنوز تست خودکار کامل برای منطق حسابداری وجود ندارد. پیش از انتشار باید حداقل موارد زیر به PHPUnit و تست یکپارچه روی WordPress/WooCommerce تبدیل شوند:

1. نبود PDO_SQLite: فعال‌سازی با پیام روشن متوقف شود و هیچ داده‌ای حذف نشود.
2. مهاجرت: اجرای دوباره migration نباید جدول/داده تکراری بسازد.
3. تراکنش: خطای میانه عملیات باید همه تغییرات SQLite را rollback کند.
4. توازن: سند نامتوازن نباید قطعی شود.
5. idempotency: پردازش دوباره سفارش/فاکتور خرید نباید سند یا موجودی تکراری بسازد.
6. رقابت موجودی: دو سفارش هم‌زمان آخرین کالا را oversell نکنند.
7. قیمت خرید: تغییر قیمت خرید آینده نباید COGS سفارش قدیمی را تغییر دهد.
8. تأمین مستقیم: موجودی انبار خودی به‌صورت صوری تغییر نکند.
9. لغو و مرجوعی: سند اصلی باقی بماند و سند اصلاحی مرتبط ساخته شود.
10. HPOS: تست با HPOS روشن و خاموش، بدون SQL مستقیم روی جداول سفارش.
11. پیامک خاموش: حسابداری بدون افزونه پیامک کار کند.
12. بکاپ: دیتابیس در حالت WAL بکاپ و restore موفق داشته باشد.
13. امنیت: capability، nonce، escaping، SQL injection و دسترسی مستقیم فایل بررسی شوند.
14. کارایی: تست بار خواندن/نوشتن و قفل SQLite روی هاست مشابه محیط تولید اجرا شود.

هیچ نسخه‌ای تا پاس شدن تست‌های بحرانی نباید به عنوان حسابداری عملیاتی معرفی شود.
