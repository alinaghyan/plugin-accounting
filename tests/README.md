# برنامه آزمون

تست‌های smoke فعلی برای schema، گردش خرید، پرداخت‌های مرحله‌ای، مرجوعی و فروش/COGS و دریافت مشتری در پوشه `tests/` قرار دارند و در GitHub Actions اجرا می‌شوند. این تست‌ها جای تست کامل PHPUnit و آزمون روی WordPress/WooCommerce واقعی را نمی‌گیرند. موارد زیر همچنان باید پیش از انتشار بررسی و به تست خودکار تبدیل شوند:

1. نبود PDO_SQLite: فعال‌سازی با پیام روشن متوقف شود و هیچ داده‌ای حذف نشود.
2. مهاجرت: اجرای دوباره migration نباید جدول/داده تکراری بسازد.
3. تراکنش: خطای میانه عملیات باید همه تغییرات SQLite را rollback کند.
4. توازن: سند نامتوازن نباید قطعی شود.
5. idempotency: پردازش دوباره سفارش/فاکتور خرید نباید سند یا موجودی تکراری بسازد.
6. رقابت موجودی: دو سفارش هم‌زمان آخرین کالا را oversell نکنند.
7. قیمت خرید: تغییر قیمت خرید آینده نباید COGS سفارش قدیمی را تغییر دهد.
8. تأمین مستقیم: موجودی انبار خودی به‌صورت صوری تغییر نکند.
9. لغو و مرجوعی: سند اصلی باقی بماند و سند اصلاحی مرتبط ساخته شود.
10. HPOS: تست با HPOS روشن و خاموش، بدون SQL مستقیم روی جداول سفارش.
11. پیامک خاموش: حسابداری بدون افزونه پیامک کار کند.
12. بکاپ: دیتابیس در حالت WAL بکاپ و restore موفق داشته باشد.
13. امنیت: capability، nonce، escaping، SQL injection و دسترسی مستقیم فایل بررسی شوند.
14. کارایی: تست بار خواندن/نوشتن و قفل SQLite روی هاست مشابه محیط تولید اجرا شود.

هیچ نسخه‌ای تا پاس شدن تست‌های بحرانی نباید به عنوان حسابداری عملیاتی معرفی شود.

- تست فروش و دریافت مشتری باید Outbox، COGS، توازن اسناد، مانده دریافتنی، idempotency، رد اضافه‌دریافت و تغییرناپذیری سوابق دریافت را پوشش دهد.

- تست مرجوعی فروش باید کنترل مقدار قابل برگشت، تخصیص مالیات ردیفی، بازگشت COGS و موجودی، توازن سند، idempotency، محدودیت بستانکاری مشتری و استرداد بیش از حد را پوشش دهد.

- تست تطبیق WooCommerce باید سفارش موجود، سفارش جاافتاده، Outbox تکراری، رویداد ناموفق، سفارش دارای refund پیش از ثبت اولیه، صفحه‌بندی و ثبت گزارش immutable را پوشش دهد.

- تست همگام‌سازی موجودی باید تطبیق کاردکس، مدیریت موجودی روشن/خاموش، موجودی تنوع والد، توقف با Outbox باز، cursor دسته‌ای و ثبت مقادیر قبل/بعد را بررسی کند.

- گزارش‌ها باید P&L، سود سفارش/محصول/کانال پس از مرجوعی و ارزش موجودی با محاسبه integer و تفکیک ارز را پوشش دهند.

- تست صندوق/بانک باید جهت بدهکار/بستانکار دریافت، پرداخت هزینه، انتقال دوطرفه، مانده ارزی، جلوگیری از اضافه‌برداشت، idempotency، اثر بر سود و زیان و تغییرناپذیری تراکنش را بررسی کند.

- تست مغایرت بانکی باید اعتبارسنجی مانده ابتدا/انتها، ورود CSV، تشخیص واریز/برداشت، تطبیق فقط روی حساب/ارز/مبلغ/جهت درست، بازه تاریخ، جلوگیری از تطبیق تکراری، لغو/بازگردانی و تغییرناپذیری رویدادها را پوشش دهد.
