# MaliDev Accounting & ERP

افزونه حسابداری و مدیریت عملیات فروشگاه ووکامرس — نسخه اسکلت فنی (در حال توسعه)

> **هشدار:** این نسخه اولیه و آزمایشی است. هنوز برای ثبت حسابداری واقعی، محاسبه سود قطعی، صدور فاکتور قانونی یا استفاده در فروشگاه عملیاتی تأیید نشده است. پیش از استفاده عملیاتی باید تست‌های یکپارچه، آزمون فشار، بازبینی امنیتی و تطبیق با حسابدار انجام شود.

## هدف پروژه

ساخت یک سیستم یکپارچه برای مدیریت فروش سایت و فروش تلفنی/حضوری، خرید از تأمین‌کنندگان، بهای تمام‌شده، انبار، دریافت و پرداخت، اسناد دوطرفه و گزارش‌های مالی؛ با حفظ سازگاری با WooCommerce و افزونه‌های مستقل MaliDev.

## نصب و پیش‌نیاز

- WordPress و PHP 8.1 یا بالاتر
- WooCommerce برای امکانات فروشگاهی (در این اسکلت اجباری نیست)
- افزونه PHP با نام **PDO_SQLite** فعال باشد.
- PHP اجازه ساخت پوشه و فایل دیتابیس را داشته باشد.
- فضای ذخیره‌سازی خصوصی و قابل پشتیبان‌گیری در دسترس باشد.

فایل دیتابیس در اولویت خارج از ریشه عمومی سایت ذخیره می‌شود. اگر مسیر خصوصی قابل استفاده نباشد، افزونه مسیر محافظت‌شده داخل `wp-content` را امتحان می‌کند و فایل‌های منع دسترسی را ایجاد می‌کند. در سرورهایی که Nginx یا تنظیمات خاص دارند، مدیر سرور باید دسترسی مستقیم HTTP به مسیر داده را نیز مسدود کند.

## نصب توسعه‌ای

1. این شاخه را دریافت و پوشه `plugin-accounting` را در `wp-content/plugins/` قرار دهید.
2. مطمئن شوید PDO_SQLite فعال است.
3. افزونه را از پیشخوان فعال کنید.
4. از منوی «حسابداری MaliDev» وضعیت اتصال و دیتابیس را بررسی کنید.

**این نسخه هیچ سند مالی یا سفارش ووکامرسی را خودکار ثبت نمی‌کند.** اتصال رویدادهای فروش تا زمان پیاده‌سازی صف همگام‌سازی، ثبت idempotent و جبران خطا عمداً فعال نشده است.

## تصمیمات معماری مهم

- SQLite فقط مخزن داده اختصاصی حسابداری است؛ جداول اصلی WordPress/WooCommerce دست‌کاری نمی‌شوند.
- ارتباط با WooCommerce از APIها و هوک‌های رسمی انجام خواهد شد؛ HPOS باید پشتیبانی شود.
- به دلیل نبود تراکنش مشترک بین SQLite و MySQL، همگام‌سازی باید مبتنی بر outbox/inbox، شناسه یکتا، retry و reconciliation باشد.
- مقادیر مالی به صورت عدد صحیح و بدون float ذخیره می‌شوند. واحد پول و ضریب اعشار باید در تنظیمات مشخص شوند.
- اسناد قطعی حذف فیزیکی نمی‌شوند؛ اصلاح با سند معکوس/اصلاحی و audit trail انجام خواهد شد.
- هیچ افزونه جانبی نباید مستقیماً جداول داخلی این افزونه را تغییر دهد؛ API و hookهای نسخه‌بندی‌شده ارائه می‌شوند.
- نصب یا غیرفعال‌سازی افزونه نباید سفارش‌ها یا داده‌های WooCommerce را حذف کند.
