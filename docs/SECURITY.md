# امنیت و پایداری

- تمام صفحات مدیریتی باید capability اختصاصی و کنترل دسترسی سمت سرور داشته باشند.
- ورودی‌ها validate و خروجی‌ها escape شوند؛ کوئری‌ها فقط prepared statement.
- هر عملیات مالی باید داخل تراکنش SQLite باشد و در شکست rollback شود.
- کلید idempotency برای جلوگیری از دوباره‌کاری در سفارش، پرداخت، خرید و webhook الزامی است.
- فایل دیتابیس، WAL و SHM نباید از وب قابل دریافت باشند؛ مسیر خارج از web root ترجیح دارد.
- مسیر fallback داخل wp-content فقط با کنترل Apache/IIS محافظت می‌شود؛ برای Nginx باید قانون deny صریح در سطح سرور اعمال شود.
- بکاپ دیتابیس باید با روش سازگار SQLite انجام شود؛ کپی ساده فایل در زمان فعال بودن WAL ممکن است بکاپ ناقص بسازد.
- خطاهای حساس و اطلاعات مشتری نباید در log عمومی یا پیام خطا افشا شوند.
- نقش حسابدار و مجوز دیدن سود باید مستقل و حداقلی باشند.
- اسناد قطعی حذف فیزیکی نمی‌شوند؛ اصلاح از مسیر سند معکوس انجام می‌شود.
- قفل دوره مالی، audit log تغییرات و محدودیت ویرایش باید پیش از استفاده عملیاتی کامل شوند.
- افزونه‌های جانبی فقط از API عمومی نسخه‌بندی‌شده استفاده می‌کنند.
- هیچ داده مالی با غیرفعال‌سازی یا حذف افزونه پاک نمی‌شود.
- پیش از هر به‌روزرسانی schema، بکاپ قابل بازیابی گرفته شود.
