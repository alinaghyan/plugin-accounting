# معماری فنی

## مرزبندی مسئولیت‌ها

- **WooCommerce:** مرجع سفارش فروشگاهی، مشتری و کاتالوگ محصولات.
- **MaliDev Accounting:** مرجع اسناد مالی، دفتر روزنامه، بهای تمام‌شده، گردش انبار حسابداری و طرف‌حساب‌ها.
- **SQLite:** پایگاه داده اختصاصی افزونه؛ هیچ جدول هسته WordPress یا WooCommerce را جایگزین نمی‌کند.
- **افزونه فاکتور:** مصرف‌کننده API خواندنی اطلاعات فاکتور؛ منبع مستقل ثبت مالی نیست.
- **افزونه پیامک:** مصرف‌کننده رویدادهای مجاز؛ خاموش بودن آن نباید بر حسابداری اثر بگذارد.

## اصل سازگاری بین دو پایگاه داده

SQLite و MySQL تراکنش مشترک ندارند. در نتیجه هیچ عملیات حساس نباید فرض کند نوشتن در هر دو دیتابیس اتمیک است. راهکار هدف:

1. دریافت رویداد رسمی WooCommerce.
2. ساخت event با کلید یکتای پایدار و ثبت در outbox.
3. پردازش idempotent و ذخیره مرجع سفارش/رویداد.
4. ثبت سند و گردش انبار در یک تراکنش SQLite.
5. ثبت نتیجه و امکان retry کنترل‌شده.
6. اجرای reconciliation دوره‌ای برای کشف اختلاف‌ها.

تا تکمیل این سازوکار، اتصال خودکار فروش عمداً غیرفعال می‌ماند.

## دفتر دوطرفه

هر سند قطعی باید حداقل دو ردیف داشته باشد و مجموع بدهکار با بستانکار برابر باشد. مبلغ‌ها integer و در واحد خرد پول ذخیره می‌شوند؛ استفاده از float ممنوع است. هر سند شماره یکتا، تاریخ، منبع، ایجادکننده و وضعیت دارد.

اسناد قطعی حذف نمی‌شوند. ابطال باید با سند معکوس و ارتباط به سند اصلی پیاده‌سازی شود. قفل دوره مالی نیز پیش از عرضه عملیاتی الزامی است.

## بهای تمام‌شده

روش پیش‌فرض برنامه‌ریزی‌شده: میانگین موزون دائمی به تفکیک محصول/تنوع و انبار. مقدار و هزینه با مقیاس صحیح ذخیره می‌شود. بهای تمام‌شده هر ردیف فروش در زمان قطعی شدن خروج کالا snapshot می‌شود؛ تغییر خرید بعدی نباید سود سفارش گذشته را تغییر دهد.

## انبار و تأمین

موجودی فیزیکی، رزروشده، قابل تأمین از شرکت و پیش‌سفارش چهار مفهوم جدا هستند. موجودی شرکت فقط با تأیید معتبر و دارای زمان آخرین تأیید قابل نمایش است و نباید به موجودی فیزیکی انبار خودی اضافه شود. تأمین مستقیم مشتری مسیر گردش مستقل دارد.

## ساختار توسعه

ماژول‌ها باید از طریق سرویس‌ها و قراردادهای عمومی نسخه‌بندی‌شده ارتباط بگیرند. دسترسی مستقیم افزونه‌های دیگر به جداول داخلی ممنوع است. HPOS و CRUD رسمی WooCommerce الزامی است؛ استفاده از SQL مستقیم روی جداول سفارش‌ها ممنوع.
