# راهنمای عملیات SQLite

## پیش‌نیاز سرور
- PDO و PDO_SQLite فعال باشد.
- مسیر داده برای کاربر PHP قابل نوشتن باشد.
- فضای دیسک و inode کافی باشد.
- در صورت استفاده از fallback داخل wp-content، وب‌سرور باید دسترسی HTTP به کل پوشه و فایل‌های جانبی SQLite را مسدود کند؛ فایل .htaccess برای Nginx کافی نیست.

## هم‌زمانی
SQLite برای بار نوشتن هم‌زمان زیاد به اندازه سرور دیتابیس client/server مناسب نیست. busy_timeout و WAL در این اسکلت فعال می‌شوند، اما WAL روی همه فایل‌سیستم‌ها/هاست‌ها مناسب نیست. آزمون هم‌زمانی روی هاست واقعی ضروری است. اگر قفل‌های پرتکرار یا زمان انتظار مشاهده شد، باید قبل از بهره‌برداری معماری ذخیره‌سازی بازبینی شود.

## بکاپ
برای بکاپ آنلاین از SQLite Backup API یا ابزار سازگار استفاده شود. هنگام WAL، فقط فایل اصلی را کپی نکنید؛ تراکنش‌های تأییدنشده ممکن است در فایل‌های WAL باشند. بکاپ باید به‌صورت زمان‌بندی‌شده، رمزگذاری‌شده و با تست restore انجام شود.

## حدود اتمیک بودن
تراکنش SQLite فقط داده‌های SQLite را پوشش می‌دهد و با MySQL ووکامرس مشترک نیست. برای همین الگوی outbox، retry، idempotency و reconciliation الزامی است. عملیات مالی تا تکمیل این لایه به رویدادهای زنده WooCommerce متصل نمی‌شود.

## تغییر مسیر داده
در صورت نیاز می‌توان در wp-config.php ثابت MDA_PRIVATE_DATA_DIR را به یک مسیر مطلق خارج از web root تنظیم کرد. مسیر باید متعلق به کاربر PHP باشد و از دسترسی عمومی وب خارج باشد. تغییر مسیر پس از ایجاد دیتابیس نیازمند انتقال امن فایل و WAL/SHM در حالت توقف نوشتن است.
